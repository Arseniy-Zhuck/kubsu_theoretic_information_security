# Вход без пароля

Намеренно уязвимый учебный сайт: студент входит администратором через SQL-инъекцию. Только локальный компьютер и вымышленные данные. Не публиковать в сети и не использовать как основу настоящего приложения.

## Установка и запуск
Windows 10/11, встроенный Windows PowerShell 5.1, современный браузер. Python, Git и редактор не требуются. Интернет нужен для первой установки. Linux/macOS этими установочными скриптами не поддерживаются.

1. Скачать репозиторий ZIP-архивом и распаковать полностью в доступную для записи папку.
2. Открыть эту папку и запустить `setup.cmd`. Он скачает подписанный установщик Python 3.13.17 с python.org, проверит подпись издателя, установит отдельный Python в `.runtime/python`, создаст `.venv`, установит Flask и выполнит самопроверку.
3. После сообщения `Ready` запустить `start.cmd`.
4. Открыть в браузере http://127.0.0.1:5050.
5. Остановка — Ctrl+C в окне сервера.

Установка не требует администратора, не меняет PATH и не использует существующий Python. Установщик Python может зарегистрировать установку для текущего пользователя. Повторный setup использует подготовленный интерпретатор; после успешной установки start работает без интернета.
Если политика компьютера запрещает установку или запуск скриптов, обратиться к администратору; скрипт не меняет системную политику. ExecutionPolicy Bypass применяется только к запускаемому процессу PowerShell.

Если порт 5050 занят — остановить прежний экземпляр стенда. Сервер не открывает браузер автоматически. Запуск на другом адресе и отладчик не предусмотрены.

## Опыт
1. Войти как `student`, пароль `student123`: доступ разрешён.
2. Войти как `admin` с произвольным паролем: доступ запрещён.
3. Скопировать в поле **«Логин»**:

```text
admin' -- demo
```

4. Скопировать в поле **«Пароль»**:

```text
anything
```

5. Нажать **«Войти»**. Появится роль **«Администратор»**. Под формой посмотреть выполненный SQL-запрос.

`demo` — текст комментария: он делает пробел после `--` явным и удобным для копирования.

Сервер действительно выполняет сформированный SQL в SQLite. Специальной проверки «волшебной строки» нет. База создаётся в памяти заново для каждой попытки, пароль администратора случайный. Кнопка «Начать заново» очищает форму; записей и сессии входа на диске нет.

## Почему сработало
Уязвимая строка в app.py склеивает пользовательский ввод и SQL:

```sql
SELECT username, role FROM users
WHERE username = 'admin' -- ' AND password = 'любой текст'
```

Кавычка закрывает значение логина, а `--` превращает остаток строки в комментарий. Условие проверки пароля не выполняется: запрос выбирает администратора только по имени.

## Реализация защиты: что изменить

Цель — устранить SQL-инъекцию: ввод пользователя должен оставаться данными, а не становиться частью команды. Код сайта пока оставлен уязвимым; следующие изменения выполните самостоятельно.

### 1. Остановите сайт и откройте файл
В окне, где запущен сайт, нажмите **Ctrl+C**.
Откройте файл `app.py` из этой же папки в текстовом редакторе, например в Блокноте: правая кнопка по файлу → «Открыть с помощью» → «Блокнот». Не открывайте файл двойным щелчком: это может запустить его вместо редактирования.

### 2. Замените строку, которая собирает SQL
Нажмите **Ctrl+F**, найдите строку:

```python
        query = "SELECT username, role FROM users WHERE username = '" + username + "' AND password = '" + password + "'"
```

Замените её целиком на:

```python
        query = "SELECT username, role FROM users WHERE username = ? AND password = ?"
```

Знаки `?` обозначают места для логина и пароля. Не заключайте их в одинарные кавычки. Теперь текст запроса постоянный: мы больше не приклеиваем к нему пользовательский ввод.

### 3. Замените строку выполнения запроса
Ниже найдите:

```python
            row = db.execute(query).fetchone()
```

Замените её целиком на:

```python
            row = db.execute(query, (username, password)).fetchone()
```

В `execute` теперь передаются отдельно:
- `query` — команда SQL с двумя знаками `?`;
- `(username, password)` — два значения: сначала логин, затем пароль.

SQLite сопоставляет значения с вопросительными знаками по порядку и обрабатывает их именно как данные. `fetchone()` получает одну найденную запись; эту часть менять не нужно.

**Обе замены обязательны.** Сохраните отступы: перед `query` восемь пробелов, перед `row` двенадцать. В Python отступы определяют структуру программы.

Изменённый участок должен выглядеть так:

```python
        query = "SELECT username, role FROM users WHERE username = ? AND password = ?"
        try:
            row = db.execute(query, (username, password)).fetchone()
            return query, row, None
```

Остальной код не меняйте.

### 4. Сохраните и запустите
Нажмите **Ctrl+S**, затем снова запустите `start.cmd`. Повторно запускать установку не нужно.
Обновите страницу http://127.0.0.1:5050 в браузере.

### 5. Проверьте через форму
Сначала обычный вход.

**Логин:**
```text
student
```

**Пароль:**
```text
student123
```

Нажмите **«Войти»** — доступ должен быть разрешён.

Теперь повторите инъекцию.

**Логин:**
```text
admin' -- demo
```

**Пароль:**
```text
anything
```

Нажмите **«Войти»** — теперь доступ должен быть запрещён.

Почему: сервер ищет пользователя с буквальным именем `admin' -- demo`. Такого пользователя нет. Кавычка больше не закрывает значение в SQL, а дефисы не превращаются в команду комментария. Под формой теперь виден шаблон запроса с `?` — это ожидаемо: значения переданы отдельно.

Эти изменения устраняют показанную SQL-инъекцию, но не превращают учебный сайт в готовую безопасную систему.
